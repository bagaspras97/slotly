# ADR-000: Decision Title

## Status

Proposed

Allowed values: Proposed, Accepted, Superseded, Rejected.

## Date and owners

Record the decision date and responsible people.

## Context

Describe the problem, constraints, current behavior, why a decision is needed now, and what happens if no decision is made.

## Decision drivers

List relevant criteria such as correctness, security, simplicity, learning value, deadline, operational cost, developer experience, performance, maintainability, and portability.

## Considered options

### Option A

Describe the option, advantages, disadvantages, and risks.

### Option B

Describe the option, advantages, disadvantages, and risks.

### Option C

Keep this section only when a third credible option exists. Describe its advantages, disadvantages, and risks.

## Decision

State the selected option and why it best satisfies current drivers.

## Consequences

### Positive

Record expected benefits.

### Negative

Record accepted costs and limitations.

### Neutral

Record changes that are neither clearly positive nor negative.

## Security and data impact

Describe authentication, authorization, sensitive-data, migration, and failure impact. Use `No material impact` when appropriate.

## Verification

Describe how the decision will be validated using tests, concurrent requests, query plans, metrics, security review, deployment exercise, or developer feedback.

## Revisit conditions

List evidence or product changes that should trigger reconsideration.

## Related tickets and decisions

List relevant ticket and ADR identifiers. Use `None` when there are no related records.
